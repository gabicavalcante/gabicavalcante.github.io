{{- /* Emits JSON-LD structured data: a machine-readable statement of what the page is. The site had none -- the only machine-readable markup was the theme's BreadcrumbList RDFa on the nav, which this same file's breadcrumb block replaced; see the note further down. Two types, which is all a personal blog needs: - BlogPosting on posts. A subtype of Article; Google treats every Article subtype the same for rich results. TechArticle would also be defensible for the tutorials, but it exists for technical documentation and adds properties this site would leave empty. - Person on /about/, carrying sameAs to Github and Linkedin. This is the one that matters here: it is what lets a search engine resolve "Gabriela Cavalcante", this domain and those profiles as ONE entity rather than three unrelated pages. Both Person nodes -- the standalone one and the author on each post -- carry the same @id and the same url. Without a shared @id a consumer has to infer from name and sameAs that they are the same person, which defeats the point. The author node is repeated inline rather than reduced to an {"@id": ...} reference, because consumers that do not resolve references still get the whole node. No `image`: the site has no og:image either and inventing one is worse than omitting it. Article has no REQUIRED properties, so this costs the image treatment in a result and disqualifies nothing. Built as a dict and passed through jsonify rather than written as literal JSON, so quotes and accents in a title cannot produce invalid JSON. jsonify uses Go's encoding/json with HTML escaping on, so the angle brackets and ampersand come out as \u003c \u003e \u0026 -- a literal inside a title therefore cannot terminate the block. safeJS is required: without it the escaper quotes the whole JSON into a single string literal. htmlUnescape on the description is NOT optional. seo-description.html ends in `truncate`, which HTML-escapes and returns template.HTML -- correct for an HTML attribute, wrong here, because jsonify would then encode the already escaped text and a consumer would read back `&` for `&`. */ -}} {{- $author := .Site.Params.author -}} {{- $personID := printf "%s#person" (.Lastmod.Format "2006-01-02")) }}{{ end -}} {{- with .Params.tags }}{{ $s = merge $s (dict "keywords" .) }}{{ end -}} {{- $schema = $s -}} {{- else if and .File (eq .File.Path "about/index.md") -}} BreadcrumbList, built from the page's actual ancestors. The theme marked up the NAV MENU as one: the same three links in the same order on every page, never containing the page you are on. Search Console rejected it as well: "field id is missing in itemListElement.item". The mechanism is not the obvious one. RDFa Core 1.1 §7.5 resolves @href as the typed resource, and a conformant parser reads the old markup as schema:item (verified with pyRdfa3); the blank node is only the last-resort fallback when no @resource/@href/@src is present.
